RUNNING A RELAYER

serve.mjs: static file server plus the announce / sweep / withdraw relayer. the relayer is the business.

WHAT THE RELAYER DOES

Every step of ghostpay after the payment itself is relayed. The relayer holds one or more funded runner wallets and uses them to broadcast three kinds of user payload: ERC-5564 announcements, signed sweep artifacts (type-4 EIP-7702 transactions and EIP-3009 transfers), and Privacy Pools withdrawals. The runner pays the gas on all of them. Users pay for this through the fees documented in FEES.

Static serving works without any runner. Without a runner the write endpoints return 503 and the app falls back to wallet-side announcing.

BOOT

npm install          # ethers, snarkjs, poseidon-lite
node serve.mjs       # http://localhost:8791/ (static only, no runner)

RUNNER_PK=0x… RPC_URLS=https://your-rpc node serve.mjs

A production boot with intent sweeps, withdrawals, and fee forwarding:

SWEEPER_V2=0xCC29c7723116155ccF20C7c0b8924F4747331903 \
PP_RELAY=1 \
FEE_OWNER=0x… \
TOR_PROXY=socks5://127.0.0.1:9050 \
node serve.mjs

RUNNERS

Runners are plain EOAs that sign and pay for every broadcast. Two ways to configure them:

  • RUNNER_PK: a single runner private key in the environment.
  • runners.local.json (gitignored): a pool, [{"address":"0x…","key":"0x…"},…]. Each request picks a random runner, preferring a different one than the previous request. Entries with unparseable keys are skipped with a warning.

Keys are never logged. GET /health reports runner addresses and balances only.

FUNDING RUNNERS FROM PRIVACY POOLS

The recommended funding path keeps the runner unlinked from the operator onchain:

  1. Withdraw from Privacy Pools in the app (step 4, WITHDRAW) to one or more fresh EOAs.
  2. Put those keys in runners.local.json. One 0.01 ETH withdrawal funds dozens of sweeps.
  3. Rotate any time: withdraw again to a new address, swap the key, restart.

A runner funded this way has no funding link to the operator onchain. See PRIVACY for why this matters.

NETWORKING

RPC ROTATION

Every JSON-RPC read (nonce, balance, gas, receipts) goes through rpcCall(), which shuffles RPC_URLS and tries endpoints in random order per call. No single endpoint sees the full read pattern. Broadcasts are different: signed transactions go only to BROADCAST_URLS (also random order per broadcast), never to the read rotation.

TOR

With TOR_PROXY set, all JSON-RPC routes over Tor via a socks agent (plain node https; fetch has no socks support). No RPC provider then sees both the relayer's IP and its broadcasts. The /price CoinGecko fetch routes over Tor too.

brew install tor && tor &
TOR_PROXY=socks5://127.0.0.1:9050 RPC_URLS=https://rpc.flashbots.net,https://eth.drpc.org node serve.mjs

BROADCASTING

FLASHBOTS PROTECT

The default broadcast endpoint is https://rpc.flashbots.net?fast=true: Flashbots Protect in fast mode. Transactions go to a private mempool. Explorers show nothing until the transaction is mined, which breaks the link between the HTTP request and a publicly visible pending transaction. Reads never go through Protect.

LOCAL NONCE TRACKING

Protect's private mempool is invisible to public endpoints, so their pending nonce goes stale after the first in-flight transaction and would hand out the same nonce twice. The relayer seeds each runner's nonce from the network once, then increments locally on every accepted send. Two announces were lost to the stale-nonce failure before this existed (2026-09-12).

JITTER

Broadcasts wait a random delay so the browser request and the onchain transaction are not trivially time-correlated: 2-15 seconds for announces, 5-45 seconds for sweeps and withdrawals. Fee-forward sweeps skip the jitter: they are the operator's own money movement, not user traffic.

FEES AND THE PRIORITY FLOOR

Gas is a 2x bump over current network prices (feeBump()): sweeps must land even in a fee spike. eth_gasPrice and the fee-history reward may come from different endpoints in the rotation, so both max fee and priority fee are based on the larger value and clamped. MIN_PRIORITY_WEI (default 100000000 wei, 0.1 gwei) floors the priority fee: at ultra-low gas prices an unfloored 2x bump produces a tip so small that builders skip the transaction entirely. Protect dropped two announces and a sweep that way on 2026-09-12. The floor costs cents per transaction and buys prompt inclusion.

AFFORDABILITY PREFLIGHT

Protect accepts unfunded transactions: it returns a hash, then never includes them, producing phantom pendings explorers never find. Before broadcasting, the relayer checks the runner's balance against gasLimit * maxFeePerGas + value and refuses with a loud 400 instead of broadcasting into the void.

GAS ESTIMATION

Every broadcast runs eth_estimateGas with 50% headroom. Intent sweeps hard-fail when estimation fails: a malformed intent must never burn runner gas on a reverting transaction. The fixed 500k fallback applies only to the proven legacy eip7702-sweep flow, where estimation against a not-yet-delegated EOA under-measures.

THE REAPER

Protect can silently drop a transaction it cannot include. The reaper is the backstop:

  • Every announce and intent sweep is journaled to broadcasts.jsonl (gitignored) with its full payload.
  • Every 5 minutes (first tick 10 minutes after boot) the reaper checks each open entry for a receipt.
  • After a 6-minute grace window with no receipt, the payload is rebuilt and rebroadcast with a fresh nonce. Announces are deterministic from (stealth, ephPub, metadata); an intent sweep rebroadcast is safe because a doubly-landed original fails on the consumed authorization nonce.
  • Maximum 4 attempts per payload, then the entry is marked given-up and kept in the journal for a manual look. A reverted transaction is logged loudly, never silently dropped.
  • Completed entries age out of the journal after a week.

Legacy sweeps and withdrawals are not journaled: their artifacts stay valid in the app and retrying is a user decision.

ABUSE PROTECTION

The write endpoints cost the runner gas, so a public relayer needs a brake.

RATE LIMITS

ENDPOINTLIMITSCOPE
POST /announce10 / minper IP
POST /sweep5 / minper IP
POST /pp-withdraw5 / minper IP

In-memory token buckets keyed by endpoint + IP, refilled lazily, reset on restart: a brake, not a quota. A limited request gets a clean 429 JSON error with a Retry-After header.

BEARER AUTH

With GHOSTPAY_API_TOKEN set, POST /sweep and POST /pp-withdraw additionally require Authorization: Bearer <token>. The compare is constant-time over sha256 hashes of both sides, so neither length leaks. /announce and the GET endpoints stay open. GET /health reports authRequired: true when the token is set, never the token itself.

PRIVACY POOLS WITHDRAWAL RELAY

POST /pp-withdraw is gated behind PP_RELAY=1; otherwise it returns 503. When enabled:

  • The payload shape matches what the app sends fastrelay.xyz, so the same client code works against both.
  • The groth16 circuit binds the fee terms into the proof: the context public signal is recomputed from the withdrawal data and scope, and must match. The fee recipient must be one of this server's runner addresses, and relayFeeBPS must not exceed PP_FEE_BPS (default 25).
  • The runner pays the gas. The fee accrues onchain to the runner inside the withdrawal itself (Entrypoint.relay pays feeRecipient).
  • GET /health advertises ppRelay: true and ppFeeBps so the app can discover the relay and price proofs before building one.

Only the mainnet ETH Privacy Pool is served: chainId 1, the canonical entrypoint, the ETH pool scope. Gas estimation simulates the full withdrawal including proof verification, so an invalid proof fails with a clean error instead of burning gas onchain.

FEE AUTO-FORWARD

Relayer fees accrue onchain to the runner: tx.origin on intent sweeps, feeRecipient inside withdrawals. With FEE_OWNER set, a forwarder consolidates them:

  • Every FEE_SWEEP_MINUTES (default 60; first sweep 5 minutes after boot) each runner sends its ETH balance above FEE_RESERVE_ETH (default 0.005) to FEE_OWNER as a plain type-2 transfer.
  • Forwards ride the same broadcast machinery as user transactions (RPC rotation, fee bump, BROADCAST_URLS) but skip the jitter.
  • Every forward is logged to fees.jsonl as kind: "fee-forward" so the ledger sees the outflow.
  • Unset FEE_OWNER disables the forwarder entirely. A bad address fails boot. A failed forward logs one line and waits for the next tick; it never crashes the server.

OPERATING NOTES

  • Errors are clean JSON ({"error": "…"}), never stack traces.
  • Needs ethers >= 6.14 for type-4 transactions; the server refuses to boot on older versions.
  • relay.mjs remains a standalone dumb broadcaster for saved artifacts: RUNNER_PK=0x… node relay.mjs artifact.json. It writes no ledger entries.
  • Fee revenue reporting: node fees.mjs. See FEES.
  • Endpoint payload contracts: API.
