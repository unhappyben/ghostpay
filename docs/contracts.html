StealthSweeperV2 (SweeperV2.sol)

0xCC29c7723116155ccF20C7c0b8924F4747331903 · mainnet · verified on Blockscout

The EIP-7702 delegation target for sweeps, a strict superset of the v1 sweeper. V1 signs a 7702 authorization but the relayer picks the calldata, so a malicious relayer could call sweepETH(itsOwnAddress) and take the whole balance. V2 adds executeSweep(intent, sig): every parameter of the sweep comes from an EIP-712 intent signed by the stealth key itself, so third-party relaying is trustless. A relayer that tampers with anything invalidates the signature.

EIP-712 spec

DOMAIN_TYPEHASH =
  keccak256("EIP712Domain(string name,string version,uint256 chainId,address verifyingContract)")

SWEEP_INTENT_TYPEHASH =
  keccak256("SweepIntent(uint8 action,address token,address destination,uint256 precommitment,uint256 feeBps,uint256 deadline)")

NAME_HASH    = keccak256("GhostpaySweeper")
VERSION_HASH = keccak256("1")

domainSeparator() = keccak256(abi.encode(
  DOMAIN_TYPEHASH, NAME_HASH, VERSION_HASH, block.chainid, address(this)))

hashSweepIntent(intent) = keccak256(abi.encodePacked(
  "\x19\x01",
  domainSeparator(),
  keccak256(abi.encode(SWEEP_INTENT_TYPEHASH,
    intent.action, intent.token, intent.destination,
    intent.precommitment, intent.feeBps, intent.deadline))))

Under 7702 the code executes as the stealth EOA, so address(this) is the stealth account itself: verifyingContract pins every intent to exactly one stealth address. The domain separator is rebuilt fresh in memory on every call: never cached, never immutable, because under 7702 neither storage nor immutables travel with the code.

The intent struct

FieldTypeMeaning
actionuint80 = ETH to destination · 1 = Privacy Pools ETH deposit · 2 = PP token deposit · 3 = token to destination.
tokenaddressActions 2/3 only (ignored otherwise).
destinationaddressActions 0/3 only (ignored otherwise).
precommitmentuint256Actions 1/2 only: the Privacy Pools deposit precommitment.
feeBpsuint256Relayer fee in basis points of the swept amount, paid to tx.origin. Onchain cap MAX_FEE_BPS = 1000 (10%).

executeSweep (selector 0x89cb3125) requires: not expired, fee within cap, and the recovered signer equal to address(this): a valid recovery can only ever equal the executing account. The fee pays tx.origin, not msg.sender, so batched relaying still pays the runner that paid the gas, never the dispatcher contract.

PayAndAnnounce (PayAndAnnounce.sol)

0x665E5f19FFFfBa541B3314E66bBAaCD08080cC02 · mainnet · verified on Blockscout

ERC-5564 stealth payment and announcement in one transaction. pay(stealth, ephPub, metadata) is payable: it emits the Announcement event via the canonical singleton (0x55649E01B5Df198D18D95b5cc5051630cfD45564, scheme 1) and forwards the ETH to the stealth address, atomically. If the payment cannot be delivered the whole transaction reverts, so no announcement is ever left pointing at a payment that did not happen. The contract emits nothing of its own: the singleton's Announcement event is the entire output, identical in shape to what the relayer or an EIP-5792 batch produces. payToken pulls via transferFrom, so token payments need a prior approve (or a 5792 batch of approve + payToken).

BatchRelayer (BatchRelayer.sol)

not deployed · source in the repo · deployment checklist in Relayer

Fan-out dispatcher for batched 7702 sweeps. One type-4 transaction carries up to 20 authorizations in its authorization list, then one call runs every sweep: relay() is all-or-nothing (any failed inner call reverts the batch, bubbling the reason), relaySkipFailures() is best-effort and emits one RelayFailed(index, target, reason) event per failure. One gas payment for N sweeps. Unlike the sweeper this contract executes as itself, so plain logic is fine. Fees still land on tx.origin, because executeSweep pays tx.origin, not this contract. Caveat: a batch shares one transaction, so the swept addresses are linked onchain. Deploy with no constructor args, then set BATCH_RELAYER=<address> to enable eip7702-intent-batch.

The 7702 execution model

EIP-7702 lets an EOA delegate its execution to contract code for a transaction. The mechanics that matter for the sweeper:

  • Code runs as the EOA. address(this) is the delegating stealth account. Its ETH and token balances are what the sweep moves. Calls out (Privacy Pools deposit, destination transfer, fee to tx.origin) are indistinguishable from the EOA acting itself.
  • Storage does not travel. Storage reads and writes hit the EOA's own (empty) storage, not the sweeper's. Only constants and pure code live in the bytecode, so only they survive delegation. A constructor-populated mapping would read as empty in the EOA context. This is why the pool addresses are constant and the EIP-712 domain separator is rebuilt in memory on every call.
  • The authorization is single-use per nonce. It binds the delegation target and the EOA nonce. A replayed artifact fails on the consumed nonce, which is also what makes the reaper's rebroadcasts safe.
  • The stealth EOA never needs gas. The runner sends the type-4 transaction and pays; the EOA just delegated.
